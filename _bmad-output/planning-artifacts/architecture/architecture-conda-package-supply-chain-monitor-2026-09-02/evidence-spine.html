Unknown is not clean.

A supply-chain monitor earns its keep by being believed. The expensive failure is not a missed CVE — it is a package that reads clean because a lookup failed, a mapping was never resolved, or evidence went stale unnoticed. Every decision below follows from refusing to let that happen.

Three properties of the problem

why this shape

Almost every rule in the spine traces back to one of these. They are properties of the domain, not preferences about code.

It must be believed

Someone acts — or fails to act — on the word "clean". A false clean is worse than a missing answer, because a missing answer gets chased.

→ five outcome states, never four

It must be reconstructable

Months later, someone asks why a package was flagged, or why it wasn't. That question is unanswerable if the system overwrote what it knew.

→ append-only evidence, versioned policy

Its inputs are unreliable

Source repos, PyPI, conda-forge, advisory feeds, the KEV catalog — each with its own rate limits and outages, none related to the others.

→ collectors share nothing but the log

The five states

the recurring motif

Every derived status in the system carries these. They are one enum, defined once, with fixed lowercase values and a single precedence order — and no rollup, serializer, export or generated answer is permitted to collapse them.

determinate

A real answer. Current, compliant, ready — whatever the policy computed.

unknown

We looked and could not tell. Distinct from clean, and never rendered as blank.

not_found

The source answered, and the thing is not there. An answer, not an absence.

not_applicable

The check does not apply to this package type. Never folded into clean or unknown.

error

The lookup failed. Traceable to the run and the trace id that produced it.

The counter-metric names the failure mode. Rising "percentage of packages showing clean" is tracked precisely so nobody optimizes it. Driving it up by resolving unknown or unmapped into clean would defeat the entire product while every dashboard improved.

The layers

select to inspect

Layered pipes-and-filters over an append-only log. Dependency direction is downward only — collectors never import policies, policies never import collectors or workflow, nothing imports reporting.

The two paths

sync / async boundary

The dividing line is easy to state and easy to violate. "Let me just refresh this package inline" is the most natural thing a developer will write, and it blocks a web worker on a rate-limited third party until the request times out.

The invariants

24 rules · select to expand

Each fixes something two independently-built units could otherwise choose incompatibly. ADOPTED means reality or an upstream document already settled it; NET-NEW means nothing in the codebase does this yet.

Two things people will get wrong

under deadline pressure

The inventory table is not the export

The requirements list P, Rank, Score, Work, Vuln and more as inventory fields, because that is the shape consumers read today. Every one of them is derived.

Make them columns on Package and either policy writes the package row — taking the audit trail with it — or they sit permanently null.

Projected at read time by reporting. The export keeps its headings; the models do not.

A finding is not an evidence row

Evidence is append-only, so today's row for CVE-2026-1234 is superseded tomorrow by a new row with a new id. A queue item keyed on that id resurrects as brand-new unactioned work after every re-collection, forever.

Key it on package + work_type instead and accepting one CVE accepts them all.

Key on a finding key — re-observation-stable, declared per evidence table.
