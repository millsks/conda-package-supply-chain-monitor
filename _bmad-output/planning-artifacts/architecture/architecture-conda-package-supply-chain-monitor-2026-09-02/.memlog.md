- (decision) [recovered] Principle: keep stable identity snapshots separate from volatile timestamped evidence, so identity storage is never used as the store of changing facts.
- (decision) [recovered] Principle: deterministic code and SQL make every compliance, severity and priority decision; LLMs may summarize or explain evidence but never decide.
- (decision) [recovered] Principle: preserve uncertainty — missing, failed and ambiguous states stay visible rather than collapsing into clean/current.
- (decision) [recovered] Principle: every collector workload is independently schedulable, idempotent, retryable and rate-limited.
- (decision) [recovered] Principle: every LLM-facing component gets read-only, governed database access.
- (decision) [recovered] System decomposes into six components: identity resolution service, inventory layer, independent collectors, evidence store, policy/scoring engine, reporting layer.
- (decision) [recovered] Data flow is one direction: inventory list to identity resolution to independent collectors to append-only evidence store to policy/scoring engine to current-inventory materialized view to DB-GPT/LangChain/LangFlow.
- (decision) [recovered] ADR-001: the identity schema stays the canonical one-row-per-package inventory keyed by Core_Python_Package_Name; it must never be the only storage for changing releases, CVEs, KEVs, licenses or compatibility claims.
- (decision) [recovered] ADR-002: monitoring results (versions, advisory matches, KEV status, licenses, Python 3.14 results) are append-only timestamped evidence, so current status is derived and never manually overwritten.
- (decision) [recovered] ADR-003: currency, vulnerability, KEV, license, Python 3.14, priority and work-type policy is versioned deterministic code/SQL; LLMs are confined to grounded explanations, query assistance, ticket drafts and report composition.
- (decision) [recovered] ADR-004: associator_status gates automation — verified allows automated comparisons/recommendations, inventory-derived reports at lower confidence, unmapped forbids inferring external identity or declaring a package current/clean and routes to identity review.
- (decision) [recovered] ADR-005: release authority is explicit per package in a documented order (upstream source releases, verified primary ecosystem such as PyPI, feedstock recipe, published Conda package, internal/deployed), preventing packages being marked PyPI-stale merely for not being on PyPI.
- (decision) [recovered] ADR-006: collectors are independent and write their own evidence and collection records, so one source failure cannot block unrelated monitoring areas.
- (decision) [recovered] ADR-007: the current view is a derived reporting contract — a materialized view keeping canonical inventory columns plus fixed derived statuses (source/PyPI/feedstock currency, feedstock presence, Python 3.14, license, vulnerability, KEV, remediation readiness, evidence freshness, recommended work).
- (decision) [recovered] ADR-008: DB-GPT, LangChain and LangFlow reach the database only through approved views via a read-only role with query timeouts, row limits, audit logs and no write privileges.
- (decision) [recovered] Technology: PostgreSQL or the approved relational DB, the existing org scheduler (cron/Airflow/Prefect acceptable), Python application services for Conda/PyPI ecosystem support.
- (decision) [recovered] Agent layer splits by role: LangChain tools for controlled query functions, LangFlow for workflow composition and API exposure, DB-GPT for governed natural-language SQL analytics.
- (decision) [recovered] Operational: jobs are idempotent keyed by collector, package identity, source, observation time and package version; external requests require caching, rate limits, retry/backoff, timeouts and structured errors, with freshness targets defined per collector.
- (decision) [recovered] Operational: dashboards and agent reports must show unknown, not_found, error and stale as separate states, and manual mapping overrides carry provenance and survive normal automated refreshes.
- (decision) [recovered] Risk: Python 3.14 build/import verification is a separate compute-backed capability, kept distinct from metadata inference so inferred compatibility is never reported as verified.
- (decision) [recovered] Risk: advisory and KEV source licensing/availability must be confirmed before the security collector is implemented, and ambiguous identities go to a manual review queue rather than silent inference.
