§

A transition like any other

Nothing about accepting risk earns a bespoke surface. It moves a workflow item from one state to another, it is permitted by a row in the transition table, and it writes an audit row in the same transaction as the state change. What differs is one field's requiredness.

What is reused, and the one thing that changes

  • Reused: the modal. Same min(560px, 92%) width, same 26px vertical offset, same header / body / footer bands, same ghost Cancel then primary action. One level deep, never two.
  • Reused: the resulting-state preview. .chip.plain for both states with the transition-table entry named beneath, so the reviewer can see which rule permits what they are about to do.
  • Reused: the audit guarantee. The state change and its audit row commit together, in one service function, in one transaction. Neither can survive alone.
  • Reused: server-side validation. An invalid submission returns the bound form, re-rendered by crispy-forms and swapped into the modal body. Alpine never decides whether a justification is acceptable.
  • Changed: the note is required. On the route modal the note is optional — the routing itself carries the work. Here the justification is the artifact: it is the only record of why a known finding was left open, and an acceptance without one is rejected.

And one thing that is deliberately absent

There is no expiry field and no "review again on" date. CPM-APP-S04's user-visible point is that an accepted finding stays accepted: items are keyed on a re-observation-stable finding key, so after the next collection the item does not reappear as new work. Adding a re-review date here would invent a second scheduling concept that no source defines and that nothing in v1 could act on. If acceptances should expire, that is a transition-table question, not a form field.

Do not optimise this flow for speed

CPM-SM-C2 makes time-to-close a queue item a metric and states plainly that faster is not better if overrides are recorded without a substantive reason. Nothing on this form pre-fills the justification, offers a canned reason, or remembers the last one. The friction is the feature.

Why the timestamp is not decided by the form

The when column is set by the service inside the transaction, not composed by the template and not supplied by the client. That is what makes it usable as proof: the timestamp the reviewer sees after the swap is the audit row. Nothing on the screen reports success before that row exists, so a spinner on the button while the transaction runs is correct and a row that changes before the response arrives is not.

Five columns, fixed

when · who · from · to · what happened. The same shape on the finding detail and the package detail, so a reader learns it once.

aria-invalid and aria-describedby, both wired

The error element has an id; the field carries aria-invalid="true" and an aria-describedby listing the error and the help text, in that order, so the reason is announced before the guidance. crispy-forms wires both — a template-pack concern, not a per-template one.

a11y floor

Border and fill together, never fill alone

The invalid control takes border-color: var(--crit) and background: var(--crit-wash), because the .errmsg text is what actually carries the reason and colour is never the only channel.

DESIGN §forms

Focus returns to the invalid field

Drawn here as the global focus ring on the textarea. The swap replaces the modal body only; the dialog is not torn down and re-opened, so the trap and the return target are both intact.

a11y floor

"Nothing was written" is stated, not implied

The same sentence the 500 page carries, for the same reason: a reviewer needs to know whether their decision landed. Here it is true because the service was never called.

CPM-AD-23

The concurrent-advance case looks the same

If someone advanced the item between page load and submit, the service refuses on the state mismatch and returns the bound form saying so in plain words — "this item is now routed; it was triaged when this page loaded" — and the row re-renders at its true state.

CPM-AD-22

No client-side validation exists to disagree

The required attribute is present for native browser behaviour, but the server is the only authority. There is no Alpine rule mirroring it and therefore none to drift.

It appears in full on the item and in full in the audit row. A justification that lives only in a database is not a justification the next reader can weigh.

The response re-renders the surface after the commit. The page never reloads itself under the reader, and nothing polls — this write is synchronous and must not use the in-progress state.

The item stays in the compliance queue

Accepting risk does not route it. Routing changes an item's queue field; this transition changes only its state, and the item keeps its evidence, its history and its finding key either way.

CPM-APP-S04

G-3 named this form so that it would not be invented ad hoc at implementation time. Three states, one modal shape, one required field, one transaction.
