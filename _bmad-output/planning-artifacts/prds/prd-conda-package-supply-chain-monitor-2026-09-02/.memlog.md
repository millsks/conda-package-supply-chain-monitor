- (decision) [recovered] Core_Python_Package_Name is the primary key for the canonical inventory, so every package resolves to one stable unique identity across sources
- (decision) [recovered] Adopt the existing identity snapshot schema as the canonical inventory view rather than designing a new one, scoping the PRD from MVP through Phase 3
- (decision) [recovered] Separate the inventory snapshot (identity layer) from timestamped evidence tables, because volatile monitoring facts must not be mixed into stable identity
- (decision) [recovered] Evidence is append-only and snapshot-keyed by package, source and observation time; never overwrite a finding in place, so history stays auditable
- (decision) [recovered] Current values are derived from the latest eligible evidence and always expose the evidence timestamp, so freshness is visible rather than implied
- (decision) [recovered] Blank means missing and values are never invented; multi-value fields use a semicolon separator
- (decision) [recovered] Manual mapping overrides and a verified associator_status survive automated refresh and are never downgraded unless explicitly re-resolved, so human judgment outranks the collectors
- (decision) [recovered] Unmapped packages go to a review queue and are never treated as evidence of no feedstock or no CVEs, to avoid false all-clear signals
- (decision) [recovered] Collectors are independent: each writes only to its own evidence table plus collection_runs, and one collector failing must not block the others
- (decision) [recovered] Version currency compares source, PyPI, feedstock recipe and published Conda versions using a documented per-package authority order rather than a single source of truth
- (decision) [recovered] Priority P is assigned by top-down first-match deterministic rules, with Score (1-100) ranking within a P bucket from internal usage signals
- (decision) [recovered] Work is derived independently from P, so the actionable work type is not a side effect of the priority bucket
- (decision) [recovered] Work is a closed set of eight values (fix vulnerability, create recipe, file tracking issue, already tracked, update feedstock, validate Python 3.14, review license, resolve identity)
- (decision) [recovered] Policy and license rules are versioned and data-driven, and every policy run is re-runnable against historical evidence without recollection
- (decision) [recovered] Priority output must be explainable via Priority_Bucket_Description, Priority_Source and Priority_Reason fields carried in the inventory
- (decision) [recovered] LLM components never decide policy: they query deterministic results through a read-only governed role, views only, with row limits and query timeouts
- (decision) [recovered] Every generated explanation must cite the evidence table, evidence ID and observation timestamp it used, so LLM answers are traceable to evidence
- (decision) [recovered] Sensitive internal usage fields are not sent to external LLM APIs without explicit approval; private/local model deployment for DB-GPT must be supported
- (decision) [recovered] Python 3.14 readiness defaults to cheap static metadata checks, with build/import verification as optional evidence promoted to verified
- (decision) [recovered] Collector cadences are configured independently (daily for security/KEV, daily-to-weekly for version checks, on-demand for full Python 3.14 verification) and must scale to 10,000 packages without manual batching
- (decision) [recovered] v1 scope excludes automated remediation or PR creation, historical trend dashboards beyond queryable history, and non-Python/non-Conda ecosystems
- (event) Realignment run opened against the realigned brief; PRD predates the Django platform import and its delivery model was superseded
- (override) Reverses recovered decision 1: package identity gets a surrogate integer PK with canonical_name as a unique indexed column, replacing Core_Python_Package_Name as PK. Reason: a natural Python-specific key does not survive the non-Python later phase, and a surrogate keeps evidence foreign keys narrow and makes a canonical-name correction non-cascading
- (override) Refines recovered decision 21: non-Python conda artifacts are a later phase, not a v1 exclusion. not_applicable is modeled from v1 so the later phase exercises an existing path
- (override) Refines recovered decision 18: the natural-language layer is specified as a capability with no product names; DB-GPT is removed from the requirement text and carried in the brief addendum as an unevaluated candidate
- (override) Refines recovered decisions 7 and 8: manual identity override is a permission held by the platform and engineering leadership role, exercised in the application and audited with actor, timestamp, prior value and reason
- (decision) Numbering switches to global stable FR-N ids and non-positional epic keys (EP-PLATFORM, EP-IDENTITY, EP-CURRENCY, EP-SECURITY, EP-PY314, EP-PRIORITY, EP-APP, EP-NL). Reason: reorganizing features must never renumber a requirement downstream artifacts cite
- (decision) PRD carries three light user journeys, one per role, to force specificity about entry state and where value lands without a full UX narrative
- (change) Data model (inventory contract and evidence tables) moves to Appendix A; the inventory table is split into the ORM field contract and the export column contract it projects to
- (change) Rubric findings applied: split governed reference data (FR-3, one human write) from workflow state (FR-25 queue actions), which the 'only human write' claim had conflated across FR-27, section 6 and UJ-3
- (decision) Added FR-40 feedstock presence and maintenance policy and FR-41 remediation readiness policy. Reason: Appendix A.3 listed eleven derived statuses but section 4.3 produced only nine, leaving the two that UJ-1 and UJ-2 turn on with no owning policy
- (decision) Split 'confidence' into package-identity confidence and vulnerability match confidence in the glossary and the evidence table. Reason: the term was overloaded exactly the way the glossary is careful not to overload 'identity'
- (assumption) FR-20 priority rules and score function are deliberately unspecified; the requirement is that they are versioned data with explainable output. Content tracked as Open Question 8, blocking EP-PRIORITY
- (change) Added Open Questions 8-10: priority ruleset seed, analytics-service fit to the deployment contract (the one addendum decision with no prior disposition), and the feedstock inactivity threshold
- (event) PRD rubric gate resolved; five high findings closed
- (decision) All product identifiers namespaced with a CPM- prefix (CPM-FR-n, CPM-NFR-n, CPM-SM-n, CPM-UJ-n, CPM-EP-*). Reason: the imported django-15-factor-base platform carries its own AD-1..AD-31, FR-4..FR-44, NFR-1..NFR-7, Epic and Story ids referenced across 45 files in src/, and the PRD's original bare FR-n collided across nearly the whole range -- a bare FR-17 in this repo is the platform's local-sign-in refusal condition
- (decision) Open Question 3a resolved: the inventory source is a curated watchlist of tracked packages, versioned in the repository and changed by review. conda-forge is a collector surface (CPM-FR-9, CPM-FR-10) and never an inventory source -- a public channel carries none of the internal usage signals CPM-FR-4 ranks by or CPM-FR-20 scores with, and its package count exceeds CPM-NFR-1's 10,000-package sizing several times over
- (decision) Open Question 3b resolved: internal_component_count and internal_lob_count are required on every inventory record; apps, platforms, downloads and versions are nullable. Reason: the two counts are the internal usage breadth CPM-FR-4 ranks by, and the other four cannot be credibly hand-authored while CPM-FR-20's score function is itself undecided (Open Question 8)
- (change) CPM-FR-42 reworded from "the organization's internal source" to "a declared inventory source", and gains three consequences: the required/nullable split, blank means missing and never zero, and a malformed record fails the whole run
- (change) Section 4.2 gains "A surface is not an inventory": none of the eight evidence collectors introduces a package, and conda-forge in particular is observed rather than ingested
- (change) Appendix A.2's inventory_snapshots row names the required and nullable signals rather than deferring to "internal usage signals as observed"
